Before we start: what is a program?

Three minutes of context that make everything else easier.

A program is a list of instructions, in order, that a computer follows exactly. It is like a recipe: not vague advice ("cook until nice"), but precise steps ("heat to 180 °C, wait 12 minutes").

A programming language is the notation you write those steps in. Humans write the recipe; the computer needs something much more boring and repetitive. So a program called a compiler translates what you wrote into the computer's own language.

Brick is unusual in how it does that last step: it turns your program into C, another language that has excellent free translators (gcc, clang). Those then produce the actual machine code. So Brick leans on decades of optimisation work instead of re-inventing it.

hello.brickwhat you write
→
brickthe Brick compiler
→
hello.cplain C, readable
→
gccthe optimiser
→
helloa real program
You do not need to understand the diagram. It is here so that later, when something feels like magic, you can come back and see there is no magic — just text turning into other text until it runs.

One more thing: this page does not run code inside your browser. Each program below has a Run button, and the output it shows is the real output of the real Brick compiler, copied here so you can compare.

1

Your first program

Make the computer say something.

Here is the smallest useful Brick program in existence:

hello.brick 
function main() {
    print("Hello, Brick!")
}
OutputHello, Brick!

Read it out loud, roughly: “make a function called main; inside it, print the words Hello, Brick!”

Four pieces matter:

  • function main() — every Brick program has a main. It is where the computer starts. You never call it yourself; the program does.
  • { and } — the curly braces mark the body. Everything between them belongs to the thing before them. They always come in pairs.
  • print(...) — show something on the screen, then move to a new line.
  • "Hello, Brick!" — the quotes are part of the notation, not the message. They say “this is literal text, not an instruction”.
Every character counts. Brick cares about the difference between " and ', between uppercase and lowercase, and about braces matching. If something breaks, look for a missing } or a missing quote first — it is almost always that.

Try it

Change the words inside the quotes to your own name. Keep the quotes and the parentheses where they are. What do you think happens if you delete one quote?

The compiler stops and points at the line. Text without a closing quote runs to the end of the line and the program makes no sense, so Brick refuses to build it. This is normal and good: a compiler's job is to complain early.

Numbers and math

Let the computer do the arithmetic.

print does not only print text. Give it a calculation and it works out the answer first:

math.brick 
function main() {
    print(2 + 3)
    print(10 - 4)
    print(6 * 7)
    print(20 / 4)
}
Output5 6 42 5

The symbols are the ones you already know, with two exceptions:

  • * means multiply (because × is not on a keyboard).
  • / means divide. With whole numbers the answer is rounded down: 7 / 2 gives 3, not 3.5.
  • % means “remainder”. 7 % 2 gives 1. You will meet it again in lesson 11, and it is far more useful than it looks.

Notice there are no quotes around the calculations. Quotes mean “text, exactly as written”. Without them, Brick computes.

Try it

Add a line that prints 100 - 58. Then try print(7 / 2) and print(7 % 2).

You get 42, then 3, then 1. Whole-number division throws away the fraction; % keeps only the fraction — as a remainder.

What does print(9 % 4) show?

Variables: giving a name to a value

Stop repeating yourself; store things.

A variable is a labelled box that holds a value. You make one with var, and Brick works out what kind of value it is:

variables.brick 
function main() {
    var name = "Brick"
    var year = 2026

    print("I am learning " + name)
    print(year)
}
OutputI am learning Brick 2026

Three things to notice:

  • The + sign glues text together when both sides are text. That is called concatenation, and it is why the space inside "I am learning " matters.
  • year prints as 2026, not "2026". Brick is strict about the difference between a number and text — a number can be used in math, text cannot.
  • You cannot add a number to text directly. "Year: " + 2026 is an error, on purpose. Lesson 8 shows the fix, to_text.
Names are yours to choose. age, score, temperature — anything that is a letter followed by letters, digits or underscores. Pick names you would say out loud. Future-you will be grateful.

Changing a value later is easy — just assign to it again:

changing.brick 
function main() {
    var score = 10
    print(score)
    score = 25
    print(score)
}
Output10 25

print("Age: " + 12)

4

Making decisions

Run different instructions depending on a condition.

if is a fork in the road. Brick checks a condition — something that is either true or false — and takes one path:

weather.brick 
function main() {
    var temperature = 18

    if temperature > 25 {
        print("Warm")
    } else if temperature > 15 {
        print("Mild")
    } else {
        print("Cold")
    }
}
OutputMild

The shapes to remember:

  • > greater than, < less than, >= greater or equal, <= less or equal.
  • == means “is equal to”. Yes, two equals signs. One = means “put this value in that box” (lesson 3). Mixing them up is the single most common beginner mistake.
  • != means “is not equal to”.
  • else if adds another question when the first one was false.
  • else is the “none of the above” path. It has no condition.

Brick checks from the top. 18 > 25 is false, so it asks the next question: 18 > 15 is true, so it prints Mild and skips the rest.

Indentation is for humans. The spaces at the start of lines do not change what the program does — but they show at a glance which instructions are inside which block. Brick's formatter (brick fmt) applies the standard four spaces for you.

Try it

Write a program with var score = 72 that prints "Pass" when the score is 50 or more, and "Fail" otherwise.

function main() {
    var score = 72
    if score >= 50 {
        print("Pass")
    } else {
        print("Fail")
    }
}

Change 72 to 30 and run it again — the other path is taken.

5

Repeating things

Make the computer do the boring part.

while repeats a block as long as a condition stays true. Somewhere inside you must change something, or it repeats forever:

countdown.brick 
function main() {
    var n = 3

    while n > 0 {
        print(n)
        n = n - 1
    }

    print("Liftoff!")
}
Output3 2 1 Liftoff!

Follow it step by step:

  1. n is 3. Is 3 > 0? Yes → print 3, make n 2.
  2. Is 2 > 0? Yes → print 2, make n 1.
  3. Is 1 > 0? Yes → print 1, make n 0.
  4. Is 0 > 0? No → leave the loop, print “Liftoff!”.
The classic bug. If you forget n = n - 1, the condition stays true forever and the program never stops. That is called an infinite loop. Closing the terminal, or Ctrl+C, ends it.

Try it

Print the even numbers from 2 to 10. Hint: start at 2 and add 2 each time.

function main() {
    var n = 2
    while n <= 10 {
        print(n)
        n = n + 2
    }
}

Output: 2 4 6 8 10, one per line.

What happens if the loop body never changes the condition?

Lists: many values in order

Keep a collection instead of ten separate variables.

A list holds many values of the same kind, in order. You say what kind it holds when you create it:

pets.brick 
function main() {
    var pets = List(text)
    pets.push("cat")
    pets.push("dog")

    for pet in pets {
        print(pet)
    }

    print(pets.len)
}
Outputcat dog 2

The four words you need:

  • List(text) — “an empty list of text”. Use List(int) for numbers.
  • .push(value) — add an item to the end.
  • for pet in pets — do the block once per item, with pet holding the current one.
  • .len — how many items are in it.

You can also reach a specific item by position, counting from zero: pets[0] is "cat", pets[1] is "dog".

Why zero? It is a convention shared by nearly every language, and it makes “how far from the start” and “which one is next” the same number. It feels odd for a day and then never bothers you again.

Try it

Make a list of three numbers and print their total. Hint: start var total = 0 before the loop and add each item inside it.

function main() {
    var numbers = List(int)
    numbers.push(4)
    numbers.push(10)
    numbers.push(7)

    var total = 0
    for n in numbers {
        total = total + n
    }

    print(total)
}

Output: 21.

In pets[0], which pet do you get?

Functions: naming a chunk of work

Write it once, use it many times.

A function is an instruction you invent. It can take inputs (parameters) and give back an output (a return value):

greet.brick 
function greet(name: text) -> text {
    return "Hello, " + name + "!"
}

function main() {
    print(greet("Ada"))
    print(greet("Brick"))
}
OutputHello, Ada! Hello, Brick!

Reading the signature out loud helps:

  • function greet — a function called greet.
  • (name: text) — it takes one input called name, and that input is text.
  • -> text — it hands back text. The arrow means “produces”.
  • return — the answer. It also stops the function immediately.

Then greet("Ada") becomes the text "Hello, Ada!", and print shows it. Same function, different inputs — that is the whole point.

Why bother? Because when the message changes you edit one line, not twenty. And because a well-named function turns code into something that reads like a sentence: print(greet("Ada")).

Try it

Write a function twice(n: int) -> int that returns twice its input, and print twice(21).

function twice(n: int) -> int {
    return n * 2
}

function main() {
    print(twice(21))
}

Output: 42.

Can I call it double? Yes. double is a word C uses for its own kind of number, and Brick turns your program into C, so you might expect a clash. There isn't one. Brick quietly writes bx_double in the C it produces and leaves your source alone: 
function double(n: int) -> int {
    return n * 2
}

function main() {
    print(double(21))
}

Output: 42. The same is true for the other short, obvious names C owns — long, printf, strlen, size_t, and a few dozen more. Name things whatever reads best.

Two kinds of name are still off limits, because the language itself already uses them: the type names (int, float, bool, text, bytes, void) and the built-in functions (print, exit, slice, …). You get a clear message if you try: cannot name a struct "int": int is a built-in type.

Building text

Mix numbers and words; assemble output piece by piece.

Brick will not silently turn a number into text. You ask, with to_text:

totext.brick 
function main() {
    var age = 12
    print("Age: " + to_text(age))
}
OutputAge: 12

When you need to glue many pieces together — inside a loop, say — use a Builder. It collects pieces and produces the final text once:

lines.brick 
function main() {
    var out = Builder()
    var i = 1

    while i <= 3 {
        out.add("line ")
        out.add(to_text(i))
        out.add("\n")
        i = i + 1
    }

    print(out.build())
}
Outputline 1 line 2 line 3

New pieces of notation:

  • Builder() — an empty collector.
  • .add(...) — append one piece (text, or to_text(number)).
  • .build() — hand back everything collected, as one text.
  • "\n" — a newline. Text written in quotes can contain special codes like this; \ introduces them.
Why not just + in a loop? Each + makes a brand-new copy of the whole text, so a thousand small additions copy more and more each time. A Builder appends instead, and stays fast. Use + for a few pieces, a Builder for many.

Try it

Produce exactly this, using a loop:

#1
#2
#3
function main() {
    var out = Builder()
    var i = 1
    while i <= 3 {
        out.add("#")
        out.add(to_text(i))
        out.add("\n")
        i = i + 1
    }
    print(out.build())
}

Your own types

Group related values so they travel together.

So far every variable held one value. Often things belong together: a point has an x and a y; a book has a title and a page count. A struct makes that into a single new type:

point.brick 
struct Point {
    x: int,
    y: int
}

function main() {
    var p = Point{ x: 3, y: 4 }

    print(p.x)
    print(p.y)
}
Output3 4

Reading it:

  • struct Point { ... } — declare a new type named Point.
  • The fields are named and typed, separated by commas.
  • Point{ x: 3, y: 4 } — build one with those values.
  • p.x — reach inside with a dot.

A function can change a struct in place if you ask with &mut:

move.brick 
struct Point {
    x: int,
    y: int
}

function move(p: &mut Point) {
    p.x = p.x + 1
    p.y = p.y + 1
}

function main() {
    var a = Point{ x: 1, y: 2 }
    move(&mut a)
    print(a.x)
    print(a.y)
}
Output2 3
&mut in one sentence: “let this function edit my value, not a copy of it”. Without it, move would change a copy and a would stay put. Brick makes you say which you mean, and then checks it for you.

Try it

Make a struct Book with title: text and pages: int. Create one and print its title.

struct Book {
    title: text,
    pages: int
}

function main() {
    var b = Book{ title: "The Little Brick", pages: 120 }
    print(b.title)
    print(b.pages)
}

Why does move take &mut Point instead of Point?

Choices that can't be forgotten

Enums and match: make the impossible impossible.

An enum is a type whose value is exactly one of a few named cases. Each case can carry data. Here a shape is either a circle (with a radius) or a square (with a side):

shape.brick 
enum Shape {
    Circle(int),
    Square(int)
}

function area(s: Shape) -> int {
    var result = 0
    match s {
        Shape.Circle(r) => result = 3 * r * r
        Shape.Square(side) => result = side * side
    }
    return result
}

function main() {
    print(area(Shape.Circle(2)))
    print(area(Shape.Square(3)))
}
Output12 9

Reading it:

  • Shape.Circle(int) — the case is called Circle and it carries one whole number.
  • match s { ... } — look at which case s is, and run the matching line. Shape.Circle(r) also pulls the number out under the name r.
  • The block must handle every case. Forget one and Brick says so before you ever run the program.
This is the big idea. Most bugs are “I forgot a case”. Here the compiler will not let you forget: add a new shape and every match that has not been updated is an error. That is why Brick programs use enums for results instead of magic numbers — see Result.Ok / Result.Err in the project's own examples.

Try it

Add a third case, Rect(int, int), to the enum, and a matching line in match. Notice that until you add that line, the compiler complains.

enum Shape {
    Circle(int),
    Square(int),
    Rect(int, int)
}

function area(s: Shape) -> int {
    var result = 0
    match s {
        Shape.Circle(r) => result = 3 * r * r
        Shape.Square(side) => result = side * side
        Shape.Rect(w, h) => result = w * h
    }
    return result
}

Putting it together

Two real programs from everything above.

Nothing new here — just the pieces you already have, combined.

FizzBuzz

A classic interview question. Print 1 to 15, but say Fizz for multiples of 3, Buzz for multiples of 5, and FizzBuzz for both:

fizzbuzz.brick 
function main() {
    var i = 1

    while i <= 15 {
        if i % 15 == 0 {
            print("FizzBuzz")
        } else if i % 3 == 0 {
            print("Fizz")
        } else if i % 5 == 0 {
            print("Buzz")
        } else {
            print(i)
        }
        i = i + 1
    }
}
Output1 2 Fizz 4 Buzz Fizz 7 8 Fizz Buzz 11 Fizz 13 14 FizzBuzz

Why i % 15 first? Because 15 is the multiple of both 3 and 5. Check it before the others, or you would print Fizz and never reach FizzBuzz.

Counting letters in a word

Text can be walked like a list of letters, and word[i] gives you one letter to compare. Here is a function that counts how often a letter appears:

count.brick 
function countLetter(word: text, letter: text) -> int {
    var n = 0
    var i = 0

    while i < word.len {
        if word[i] == letter[0] {
            n = n + 1
        }
        i = i + 1
    }

    return n
}

function main() {
    print(countLetter("banana", "a"))
}
Output3

Try it

Change the program to count the letter "n" in "banana". Then try counting in a word of your own.

Replace "a" with "n" and you get 2. (letter[0] takes the first letter of the text, so word[i] and letter[0] are both single letters.)

Predict the output:

function main() {
    var total = 0
    for n in numbers {
        total = total + n
    }
    print(total)
}

…where numbers holds 1, 2, 3.

Where to go next

Install it, break things, read real code.

You now know enough Brick to write and read small programs. The next step is to have it on your own machine.

Install Brick

You need two things: Go 1.24+ (to build the compiler) and a C compiler such as gcc or clang. Then, in the project folder:

terminal 
make build                 # builds ./bin/brick
./bin/brick run hello.brick

And when you want to see what your program turned into:

terminal 
./bin/brick emit hello.brick     # print the C that was generated
./bin/brick check hello.brick    # only check for mistakes, run nothing
./bin/brick fmt hello.brick      # reformat nicely

What to do first

Read the examples

examples/*.brick — each file is short and plots one idea. Run them, then change one number and run again.

Break something on purpose

Delete a brace, misspell a variable, compare text with a number. Read the error. Learning to read errors is half of programming.

Write a tiny tool

A unit converter, a word counter, a todo list that prints. Small, finished programs teach more than big unfinished ones.

Read the spec

docs/SPEC.md is the full language. Skim it once; you will recognise most of it now.

What Brick is good at

Honestly, so you pick the right projects:

  • Good: command-line tools, text and file processing, compilers and language tools, small servers, anything you would write in C but want to read like a modern language. It compiles to C and runs at C speed.
  • Not yet: threads and heavy concurrency, networking and TLS out of the box, huge third-party libraries, graphical apps. Those need pieces Brick does not ship today.

That is the whole tour. Go write something small — and when it breaks, start with a missing brace or a single = where you meant ==.

Common mistakes, and what they mean

If something goes wrong, check this list first.

What you wroteWhat Brick says / what happens
if x = 3 { ... } An error: = stores a value, it does not compare. You want ==.
a missing } “expected }” pointing at the end of the file. Count your braces.
print(Hello) Tries to find a variable called Hello. Text needs quotes: print("Hello").
print("Age: " + 12) Text and number cannot be glued. Use to_text(12).
var x = 1 then var x = 2 Already declared in this scope. Just write x = 2 the second time.
while n > 0 { print(n) } Compiles fine, runs forever. Nothing inside changes n.
xs[5] on a 3-item list The program stops with an out-of-range error. Positions are 0…len-1.
struct int { x: int } or function print(x: int) int is a type the language already has, and print is a function it already has, so neither can be reused. The message says so in words: cannot name a struct "int": int is a built-in type. (double, long and other C words are fine — Brick marks them with bx_ in the C it writes.)
a function with -> int that never returns An error: every path must give a value back.
How to read an error. The first number is the line, the second is roughly the column, then a message in plain words. Start at the line it names; if that line looks fine, the real mistake is usually a line or two above.
